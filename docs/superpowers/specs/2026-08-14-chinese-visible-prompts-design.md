# AI 可见提示词中文化设计

## 背景

冠希无限画布会直接展示 AI 返回的图片、视频、导演计划和分镜提示词。当前提示协议没有对所有可见字段设置统一语言约束，因此部分节点出现整段英文，影响阅读与编辑。

## 目标

- AI 自动生成并面向用户展示的提示词统一使用简体中文。
- H3 导演、文生图、文生视频、小说分镜和多视图工作流遵守同一规则。
- JSON 键名、接口结构、模型选择、生成参数和任务行为保持不变。
- 用户主动输入的英文，以及品牌、型号、焦段、模型名和行业缩写保持原样。

## 非目标

- 不建设通用翻译服务。
- 不机械翻译用户原文或专业术语。
- 不批量改写历史项目；历史内容在重新生成或使用 AI 润色后获得中文结果。
- 不借本次修改重构无关画布、节点或生成逻辑。

## 方案

采用双层保障。

### 第一层：模型输出协议

在 H3 导演和通用工作流分析提示词中明确规定：

- JSON 键名保持现有英文协议。
- 所有用户可见字符串值必须使用简体中文。
- 专有名词可以保留原文，但必须放在中文语句中。
- 禁止输出整段英文提示词，也不重复输出中英双语版本。

受约束字段包括图片提示词、视频提示词、负面提示词、角色描述、场景描述、镜头标题、镜头提示词、多视图角色描述及绘本内容。

### 第二层：前端规范化保护

H3 响应继续经过现有规范化入口。新增中文可读性判断：

- 中文为主的结果保持不变。
- 整段英文或英文占比异常的 AI 可见字段，不直接进入节点；使用用户原始需求和已有中文结构化规则生成回退内容。
- H3、LTX、CTA、16:9、24mm 等必要术语不参与异常判断，也不被删除。
- 视频提示词继续遵守现有长度限制和单镜头结构。

通用工作流以模型协议约束为主，不新增接口字段。已有 JSON 解析失败和空字段回退逻辑保持不变。

## 数据流

1. 用户提交创作需求。
2. 前端将中文输出协议和用户需求发送给现有 AI 接口。
3. AI 返回键名不变、可见值为中文的结构化 JSON。
4. H3 结果进入规范化流程，拦截异常英文字段。
5. 画布节点和详情区域展示中文提示词。
6. 下游生成节点继续接收原有字段，不改变调用方式。

## 测试与验收

采用测试先行：

1. 测试 H3 系统提示词明确要求所有可见字段使用简体中文。
2. 测试通用工作流提示词覆盖图片、视频、分镜、多视图和绘本字段。
3. 测试 H3 返回整段英文时，规范化结果不再直接显示该英文段落。
4. 测试中文结果保持不变，专业术语不被误删。
5. 执行 `pnpm lint`、`pnpm test`、`pnpm build`。

验收以新建工作流的实际可见提示词为中文为准；HTTP 200、构建成功或代码提交不能单独替代页面验收。

## 发布边界

- 修改在独立分支完成并以小提交记录。
- 不直接推送 `main`，不 force-push。
- 代码验证通过后再同步服务器，并通过线上页面与 `/health` 回读确认版本。
