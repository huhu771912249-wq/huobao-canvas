# 冠希画布全局视频输出尺寸设计

日期：2026-08-07

## 目标

让用户在所有视频相关入口使用同一套“最终交付尺寸”，并确保后端实际输出与界面选择一致。现有模型原生尺寸、H3 5 秒限制、SeedVR2 高清链路和原有图片/GIF 功能保持不变。

## 统一尺寸

所有入口按相同顺序展示：

1. `1280×720 横屏`
2. `720×1280 竖屏`
3. `1920×1080 高清横屏`
4. `1080×1920 高清竖屏`
5. `1080×1080 方形`
6. `自定义尺寸`

默认值保持当前任务已有选择；新任务默认 `1920×1080`。自定义尺寸必须为正偶数，宽高均限制在 `256–4096`，不允许只填一边。

## 覆盖入口

- 画布文生视频与图生视频节点。
- 视频创作中心的快速创作、小说成片和素材再创作。
- 文字叠加节点的视频字幕合成。
- `54DSP 优秀素材`：在现有逗号输入框上方增加统一预设按钮，仍允许广告运营填写 `300×100` 等图片/GIF 尺寸；视频尺寸与广告图片尺寸可以同时选择。
- 54DSP 获胜素材的 H3 视频升级确认卡，明确展示本次最终尺寸。

## 尺寸语义与数据流

界面保存统一结构：

```json
{
  "output_width": 1280,
  "output_height": 720,
  "output_size": "1280x720"
}
```

模型仍按其真实原生能力生成，例如 H3 可以先生成 `608×352`。后端再执行：

```text
原生生成 → 必要时 AI 超分 → 等比 crop_or_pad → 精确尺寸验证 → 发布
```

禁止非等比拉伸。只有媒体探测确认宽高等于用户选择后，前端才能显示对应尺寸和“已完成”。

## 质量策略

- `1280×720`、`720×1280`：以 720p 目标交付，可使用高质量缩放和精确转码。
- `1920×1080`、`1080×1920`：继续走 SeedVR2 高清链路；SeedVR2 不可用时任务失败并给出明确原因，不把普通放大伪装成 AI 高清。
- 自定义尺寸：根据最长边判断质量路径；超过 1280 长边默认尝试高清链路，最终仍必须做精确宽高验证。
- 54DSP 图片/GIF 裂变保持现有尺寸生成逻辑；只有视频输出进入视频质量链路。

## 前端交互

- 使用可点击的尺寸卡片，不依赖用户手输。
- 当前选中项有高亮，并在生成按钮上方显示“最终输出：宽×高”。
- 自定义尺寸显示宽、高两个数字输入框和即时校验信息。
- 不支持所选尺寸的模型不静默回退；按钮禁用并说明原因。
- 已保存的旧项目继续读取原比例字段；没有精确尺寸时按比例迁移到默认高清尺寸。

## 后端契约

- 所有视频生成、质量处理、文字叠加和 54DSP H3 升级接口接受 `output_width`、`output_height`。
- 服务端重新校验尺寸范围、偶数约束和模型能力，不能信任前端。
- 任务状态保存请求尺寸和实际尺寸，两者分开返回。
- 完成前使用 `ffprobe` 或等价探测验证实际宽高。
- 重试沿用原任务的目标尺寸，避免重试后尺寸漂移。

## 兼容与失败处理

- 旧项目只存 `16:9`、`9:16`、`1:1` 时，分别迁移为 `1920×1080`、`1080×1920`、`1080×1080`；不改写用户原始项目数据，直到用户再次保存。
- 旧 54DSP 图片尺寸继续有效，不能被视频预设覆盖。
- 自定义尺寸不合法时前后端都拒绝提交。
- 质量处理失败时保留原生视频和基础任务结果，H3/54DSP 子任务失败不得覆盖基础 GIF/ZIP。

## 验收

- 五个预设在所有约定入口都可见、可选择并可持久化。
- 自定义尺寸的边界、奇数、缺边和超限测试通过。
- 真实生成至少验证横屏 720p、竖屏 720p、横屏 1080p、竖屏 1080p 各一个成品。
- 每个成品使用媒体探测确认 H.264 浏览器可播放、实际宽高精确一致。
- 54DSP 图片/GIF 旧尺寸回归通过，基础任务数据不受视频尺寸新增能力影响。

## 非目标

- 本轮不改变 H3 原生时长上限。
- 本轮不承诺任意模型原生生成任意像素；尺寸是最终交付规格。
- 本轮不删除现有比例选择和旧项目兼容逻辑。
