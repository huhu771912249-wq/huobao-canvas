# DSP 胜出素材 H3 高清升级设计

日期：2026-08-07

## 目标

保留现有 `GMI 反向 -> FRW A-E GIF -> CTR/Wilson 实验` 主流程。只有实验达到样本门槛并产生胜出方案后，用户才能手动确认调用 MiniMax H3，将胜出素材升级为 5 秒、1920x1080 的高清 MP4。

本次同时修复 DSP 任务进度口径。导入完成不再等同于整条 FRW 生成任务完成。

## 产品原则

- FRW 负责低成本、多尺寸 A-E GIF 验证，H3 不替代 FRW。
- H3 必须由用户在赢家产生后手动确认，不能因刷新页面或定时任务自动消耗 GPU。
- H3 升级失败不能破坏已生成的 GIF、实验数据和下载文件。
- 页面只能展示后端真实阶段与真实进度，不能用素材导入百分比冒充生成百分比。
- 同一个 Job、母素材和胜出方案只能创建一个有效 H3 升级任务；重复点击返回原任务。

## 用户流程

1. 用户完成 GMI 反向并确认生成 FRW A-E GIF。
2. 用户把 A-E 上传 DSP，登记 Creative ID，并刷新实验数据。
3. 所有方案达到每方案 1000 曝光门槛后，Wilson CTR 产生胜出方案。
4. 赢家卡片显示“升级 H3 高清视频”。数据未达标时只显示原因，不显示可执行按钮。
5. 用户点击按钮后看到确认弹窗：母素材、胜出方案、主要指标、5 秒 H3、1080p、预计会占用云端 5090。
6. 用户确认后创建 H3 任务。当前 DSP Job 内显示排队、H3 生成、SeedVR2 超分、合成、完成或失败。
7. 完成后可直接预览和下载 MP4；失败时可重试，排队或运行时可取消。

## 方案选择

采用“DSP 后端内嵌 H3 升级任务”。不采用只在前端搭建独立画布节点，因为那会把实验赢家和视频任务拆到两个状态域；也不采用自动触发，因为无法保证成本授权和赢家稳定性。

## 数据模型

在现有 DSP Job 中新增 `h3_upgrades` 数组。每项至少包含：

```json
{
  "id": "h3-upgrade-...",
  "candidate_key": "...",
  "variant": "B",
  "source_generation_id": "...",
  "source_asset_url": "...",
  "model": "minimax-h3",
  "duration_seconds": 5,
  "ratio": "16:9",
  "quality_mode": "quality",
  "status": "queued",
  "progress": 0,
  "current_step": "等待 H3 生成",
  "task_id": "",
  "output_url": "",
  "width": 0,
  "height": 0,
  "error": "",
  "created_at": "...",
  "updated_at": "..."
}
```

幂等键固定由 `job_id + candidate_key + variant + minimax-h3 + 5s + quality` 生成。已存在 queued、running 或 completed 任务时，创建接口返回原任务。

## 后端接口

- `POST /v1/dsp-creatives/jobs/{job_id}/h3-upgrades`
  - 请求：`candidate_key`、`variant`、`idempotency_key`。
  - 服务端必须重新读取实验结果，验证 `status=ready` 且提交方案仍是当前赢家。
  - 前端传入的赢家、素材地址、提示词和指标都不能作为可信依据。
- `POST /v1/dsp-creatives/jobs/{job_id}/h3-upgrades/{upgrade_id}/retry`
  - 只允许 failed 或 cancelled 任务重试，复用同一逻辑任务记录并增加 attempt。
- `POST /v1/dsp-creatives/jobs/{job_id}/h3-upgrades/{upgrade_id}/cancel`
  - 只允许 queued 或 running 任务取消。
- 现有 Job 查询接口返回 `h3_upgrades`，前端继续复用当前轮询，不新增第二套状态源。

## H3 生成链路

1. 服务端从质量门禁通过的胜出 GIF 中选择最高质量文件，提取清晰首帧；如果 GIF 文件不可用，则回退到冻结的母素材快照。
2. 使用赢家的动作提示、品类、标题、正文和 CTA 生成 H3 视频提示词。提示词要求单镜头、主体一致、禁止模型直接绘制文字。
3. 调用现有云端 `minimax-h3` 生成 5 秒、16:9 视频。
4. 使用现有 SeedVR2 质量管线超分到 1920x1080。
5. 最终合成阶段由本地排版引擎叠加胜出标题、正文和 CTA，避免依赖视频模型生成中文文字。
6. 输出 MP4 写入现有公共素材目录，并保存实际宽高、时长、文件大小和下载地址。

真实阶段必须使用现有视频质量状态语义：

- `queued`
- `cloud_generate`
- `upscaling`
- `composing`
- `completed`
- `failed`
- `cancelled`

## 进度修复

基础 DSP Job 与可选 H3 升级使用两条独立进度，不互相伪装。

基础 DSP Job 进度：

- 下载/导入：0-20%，按 `completed_creatives / total_creatives`。
- GMI 反向：20-40%，按完成的反向结果数量。
- 等待费用确认：固定 40%。
- FRW A-E 生成：40-90%，按实际 completed 或 failed 的生成项除以预期 `母素材数 x 5`。
- 打包与质量检查：90-99%。
- `completed` 或 `completed_with_errors`：100%，同时保留成功/失败数量。

如果任务仍为 `generating`，即使导入素材已经 2/2，也不能显示 100%。显式后端 `progress_percent` 优先于前端推算；旧任务没有该字段时才使用兼容推算。

H3 升级进度由视频质量任务返回，不并入基础 Job 的 100%：

- 排队 0-5%
- H3 生成 5-60%
- SeedVR2 超分 60-90%
- 排版合成 90-99%
- 完成 100%

## 前端界面

- 在每个实验来源的赢家区增加独立 H3 升级卡片。
- 数据不足时展示“尚未达到 1000 曝光/方案”，不允许调用。
- 数据达到门槛后展示赢家方案、CTR、Wilson、素材缩略图和确认按钮。
- 确认弹窗必须明确“调用云端 5090”“5 秒”“1080p”“需要消耗模型资源”。
- 提交后按钮变为状态卡，展示真实阶段、百分比、错误、重试、取消、预览和下载。
- 已完成任务再次进入页面时直接回显结果，不重复创建。

## 错误与恢复

- 实验赢家在确认前发生变化：返回 409，并要求刷新实验数据。
- 缺少质量合格的胜出素材：返回 422，保留原 GIF 结果。
- H3 或 SeedVR2 失败：升级任务标记 failed，记录可读错误；基础 DSP Job 不降级为 failed。
- 服务重启：从持久化 `task_id` 恢复轮询，不能新建重复任务。
- 输出文件缺失：页面显示“结果文件不可用”，允许重试，不显示伪下载链接。

## 测试

### 前端

- 生成中任务不会因 `completed_creatives=total_creatives` 显示 100%。
- 实验未 ready 时没有可执行 H3 按钮。
- ready 且存在赢家时显示确认入口。
- 提交后正确展示 queued、生成、超分、合成、完成和失败。
- 重复点击不会发送第二个不同幂等请求。

### 后端

- 非赢家、样本不足和过期赢家全部拒绝。
- 同一幂等键只创建一个 H3 任务。
- H3 使用服务端解析出的素材和提示词，忽略客户端伪造值。
- H3 失败不改变基础 GIF Job 的完成状态。
- 重启后可恢复任务，重试和取消符合状态机约束。
- 进度分段和旧任务兼容推算准确。

### 线上验收

- 使用一个满足实验门槛的测试 Job 手动确认一次。
- 看到 `cloud_generate -> upscaling -> composing -> completed` 真实迁移。
- 公网 MP4 返回 HTTP 200，可播放，实际尺寸为 1920x1080，时长约 5 秒。
- 页面刷新后仍回显同一升级任务与结果。
- 验收后确认没有第二条重复 H3 任务。

## 非目标

- 不自动调用 H3。
- 不用 H3 替换 FRW A-E GIF。
- 第一期不做 10 秒以上自动拼接。
- 不自动把 H3 成片上传或绑定到 DSP Creative ID。
- 不改变现有 A-E 实验门槛与 Wilson 赢家算法。

## 完成标准

- 进度条不再在等待 FRW 时显示 100%。
- 只有服务端确认的成熟赢家能创建 H3 升级。
- 用户明确确认后只产生一条 H3 任务。
- H3 任务具备真实进度、预览、下载、取消、失败重试和重启恢复。
- 真实线上验收得到可播放的 1920x1080、约 5 秒 MP4。
